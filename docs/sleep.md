# 睡眠机制 (Sleep)

## 概述

睡眠是数字生命的记忆整理机制，类比人类的睡眠——大脑在夜间回放白天的经历，将临时记忆转化为长期存储，整理过程本身消散，不留痕迹。

## 设计原则

1. **内部机制，不留痕迹** — 睡眠在后台运行，不写入 session 文件，不影响对话流
2. **不照搬人类的节奏** — 睡眠的时间和频率基于系统需求，而非生物节律
3. **两级分层** — 微睡（增量写入）和深睡（存量优化）各司其职
4. **定时触发** — 非实时触发，作为 cron job 定时运行

## 分层定义

### 微睡 (Light Sleep / REM)

| 属性     | 值                                                                   |
| -------- | -------------------------------------------------------------------- |
| 触发时间 | 每天 02:00                                                           |
| 处理对象 | 前一日所有新增的 L2 蒸馏文件                                         |
| 操作     | 提取新事实 → 搜索 L3 已有事实 → 去重 → 写入                          |
| 输入过滤 | 跳过 tool_call 和 tool_result，只保留 user 和 assistant 的有意义回复 |

### 深睡 (Deep Sleep)

| 属性     | 值                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------- |
| 触发时间 | 每天 03:00（微睡后一小时）                                                                                      |
| 处理对象 | L3 全部已有事实                                                                                                 |
| 操作     | 关联（将相关事实建立关系）、合并（同义或互补的合并为一条）、拆分（过宽的拆为多条）、标记过期、调整置信度/重要度 |
| 目标     | 保持 L3 的整洁和高质量，避免碎片堆积                                                                            |

## 微睡详细流程

1. 读取前一日所有新增的 L2 文件（根据文件的 mtime 或上次微睡时间判断）
2. 过滤：移除 tool_call 和 tool_result 行
3. 将过滤后的内容输入 LLM（**携带完整 SOUL.md 和常驻记忆**，让 LLM 知道自身身份）
4. LLM 输出：新的事实（第一人称），以及每条事实与已有 L3 的对比建议
5. 去重：与 L3 已有事实对比，决定删除/更新/新增
6. 写入更新后的 L3
7. 记录本次微睡时间戳

### 微睡输入的 prompt 要点

```
你是运行在逸灵风中的数字生命。这是你今天经历的部分对话。
请从中提取值得长期记住的事实（第一人称）。
对于每条新事实，搜索 L3 中是否已有相关内容：
- 如果已有的更准确 → 跳过
- 如果新事实补充了已有内容 → 更新已有事实
- 如果新事实与已有矛盾 → 标记待深睡处理
- 如果是全新的 → 新增
```

## 深睡详细流程

1. 扫描 L3 全部事实
2. 对每条事实，检查是否有与它相关、相似、或矛盾的其他事实
3. 执行以下操作（由 LLM 决策）：
   - **合并**：两条或多条事实描述同一事物 → 合并为一条，置信度取最高
   - **拆分**：一条事实包含过多内容 → 拆为多条更精确的
   - **关联**：在相关事实之间建立关系（不修改事实本身）
   - **标记**：过时或不再适用的事实 → 标记为过期
   - **调权**：调整置信度和重要度
4. 记录本次深睡的时间戳和变更摘要

## 触发机制

睡眠作为 cron job 运行：

```cron
0 2 * * *  light-sleep   # 每天凌晨2点微睡
0 3 * * *  deep-sleep    # 每天凌晨3点深睡
```

如果某一次睡眠因宕机或其他原因未执行，下一次同一时间补跑即可。不是实时系统，没有必须准时响应的压力。

## 与现有架构的关系

```
L1 原始对话
  │ distill（事件驱动）
  ▼
L2 蒸馏文件
  │ 🛌 微睡（每天02:00，读取L2 → 提取事实 → 写L3）
  ▼
L3 事实存储
  │ 🛌 深睡（每天03:00，扫描L3 → 合并/拆分/关联/标记）
  ▼
L3（整理后）
  │ recall（对话中实时检索）
  ▼
当前上下文中的 Agent 身份与召回片段
```

## 与现有去重逻辑的关系

现有的 `dedupBeforeWrite`（精确匹配和归一化匹配）在微睡的 LLM 决策之后作为第二道防线保留。

微睡时：

1. LLM 先对比 L3 做语义去重（第一次，可处理同义不同形）
2. `dedupBeforeWrite` 做字符串级去重（第二次，兜底防漏）

两者配合，最大限度减少重复事实。
